## Running it

```
docker compose up -d
```

Then watch startup with `docker compose ps` and `docker compose logs -f`. SonarQube's own
readiness is exposed at `/api/system/status`; the orchestrator and Vortex each expose a
`/health` endpoint. With TLS on they publish no plain port: with `--edition none` reach them
through `agentic-proxy` on 8443 (orchestrator) and 8444 (Vortex), otherwise use `docker compose exec`.

Every long-running service reports healthy once it is ready. The init services prepare a volume
and then exit with code 0; `docker compose ps -a` lists them as exited, which is expected.

The project name above prefixes every container, network and volume. Run a second bundle of the
same edition on this host only after regenerating it with a different `--project-name`.

## After the first start

1. **Log in** at https://localhost:9443 with `admin` / `admin`; SonarQube asks you to change the password.
2. **Activate the licence** under Administration → Configuration → License Manager. The agentic
   features need a licence that includes them.
3. **Configure an LLM provider** under Administration → Configuration → AI Capabilities → LLM
   Providers. Its host must be in `--llm-domains`, the only hosts the agent runtimes may reach;
   regenerate with it to add one.
4. **Connect GitHub**: create a GitHub App DevOps Platform integration under Administration →
   Configuration → DevOps Platform Integrations, and bind your projects to it.
5. **Activate the agents** under Administration → Configuration → AI Capabilities.
6. **Check the agents are connected** under Administration → System: every agentic component this
   bundle runs (hunter, remediation, vortex) should report healthy. The status refreshes every 10 seconds.

## Secrets

`.env` holds an agentic request-signing secret that was generated for you — never something you
choose or pass in — plus, if you generated this bundle with `--storage s3`, your bucket
credentials. It is readable by its owner only; keep it out of version control and treat it as a
credential store. Regenerating keeps the secret; pass `--rotate-secrets` to replace it, then
restart the whole stack.

## Storage

This bundle was generated with `--storage local`. Bucket credentials and per-job LLM
provider keys are stored in plaintext under that backend — restrict access to it the same way
you would any other credential store.

### Orchestrator temporary storage

The orchestrator mounts a local disk volume at `/tmp`, separate from shared job artifacts.
Keep this volume private to one orchestrator instance. The root filesystem stays read-only
unless custom CA import requires it to be writable.

Size local disk for concurrent repository clones, Git metadata, compressed archives, and
Remediation's extracted working copies, plus logs and headroom. The extracted repository
limit is not a disk budget. Increase disk capacity before raising
`AGENTIC_DISPATCHER_MAX_EXTRACTED_REPO_SIZE` or
`AGENTIC_DISPATCHER_MAX_EXTRACTED_REPO_MEMBERS` in the shell or bundle's `.env`.
The unchanged limits are 1,000,000,000 bytes and 100,000 entries.

Agent Orchestrator and Hunter Agent `2026.5.2` support configured repository limits.
Remediation Agent `2026.5.1` retains its 1,000,000,000-byte and 100,000-entry extraction caps;
larger Remediation repositories require a future runtime release.
With the updated orchestrator image, `/tmp/agent-orchestrator` is owner-only and cleared
before the application starts, including after a crash. Do not store persistent files there.

For an existing bundle, regenerate with the updated generator and your saved inputs, keeping
`.env` and its signing secret. Recreate the enabled runtime services first with
`docker compose up -d --force-recreate hunter-runtime remediation-agent-runtime`, omitting
services absent from your bundle. Then recreate the orchestrator with
`docker compose up -d --force-recreate orchestrator`. Regeneration preserves existing secrets. Do not remove data
volumes to apply this change. Disk exhaustion fails jobs; monitor free space on the Docker host.

## Stopping it

```
docker compose down
```

Add `-v` to also remove the named volumes (database, SonarQube data, storage, signing
material) — this is destructive and cannot be undone.
